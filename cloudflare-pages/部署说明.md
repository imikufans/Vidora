# Cloudflare Pages 部署说明

## 一、先读懂：能部署什么，不能部署什么

本工具由**前端界面**和**解析后端**两部分组成：

| 部分 | 技术 | 能否跑在 Cloudflare Pages |
|------|------|--------------------------|
| 前端界面 | 纯 HTML/JS | ✅ 可以（静态托管） |
| API 代理 | Pages Functions（JS） | ✅ 可以（本包已写好） |
| 解析引擎 | Python + subprocess + execjs(Node) | ❌ 不行（Pages 只支持 JS/TS Workers 运行时，无 Python、无子进程、无常驻进程） |
| 直播流代理 | 长连接流式转发 | ❌ 不适合（Workers 有执行时长/内存限制，不适合持续拉流） |

**结论**：Cloudflare Pages 只能承载"界面 + API 转发"，真正的解析和拉流必须留在你自己的机器或云服务器上。所以本方案是：

```
浏览器 → Cloudflare Pages(静态界面) → Pages Function(API转发) → 你的解析后端(本机/云服务器) → 直播源
```

本包已备好前两环（静态界面 + API 转发函数），你只需准备"解析后端地址"并填到环境变量即可。

## 二、三种后端方案（任选其一）

### 方案 A：本机 + Cloudflare Tunnel（免费，推荐个人使用）

把你电脑上的解析服务安全地暴露成一个公网 https 地址，无需公网 IP、无需备案。

1. 安装 cloudflared（Windows）：
   - 下载 https://github.com/cloudflare/cloudflared/releases 里的 `cloudflared-windows-amd64.exe`，重命名为 `cloudflared.exe`
2. 双击 Vidora 目录下的 `一键启动.bat` 启动解析服务（保持窗口打开，监听 127.0.0.1:8899）
3. 另开一个命令行，运行：
   ```
   cloudflared.exe tunnel --url http://127.0.0.1:8899
   ```
4. 它会输出一个临时地址，形如 `https://xxxx-xxxx.trycloudflare.com`，复制它
5. 在 Cloudflare Pages 项目设置 → 环境变量里新增：
   - 变量名：`BACKEND_URL`
   - 变量值：上一步的 `https://xxxx-xxxx.trycloudflare.com`
6. 重新部署/等待生效即可。

> 注意：临时隧道地址每次重启会变，需更新 BACKEND_URL。若要固定地址，需登录 Cloudflare 账号创建命名隧道（Named Tunnel）。

### 方案 B：部署到支持 Python 的云服务器 / 容器平台

解析后端可以放到 Render、Railway、Fly.io、VPS 等支持 Python 常驻进程的地方。

1. 在服务器上放好 `web/`、`real-url/`、`DLR/`、`requirements.txt`
2. 安装依赖：`pip install -r requirements.txt`，另需 `pip install loguru distro tqdm "httpx[http2]"`
3. 启动（监听 0.0.0.0，供外部访问）：
   ```
   python web/app.py --host 0.0.0.0 --port 8899
   ```
4. 得到服务器地址（如 `https://api.yourdomain.com`）后，填入 Pages 环境变量 `BACKEND_URL`

> 注意：部分平台对云服务器 IP 有风控，解析成功率可能不如家用宽带。

### 方案 C：只用本地版（不部署 Pages）

如果只是自己用，直接双击 Vidora 目录下的 `一键启动.bat`，浏览器打开 `http://127.0.0.1:8899/` 即可，本 Pages 包可以忽略。

## 三、把前端部署到 Cloudflare Pages

### 方式 1：网页拖拽上传（最简单）

1. 登录 https://dash.cloudflare.com → Workers & Pages → Create → Pages → Upload assets
2. 项目名称随意，比如 `vidora`
3. 把本 `cloudflare-pages` 文件夹里的**全部内容**（index.html、functions 文件夹、wrangler.toml）打包成 zip 上传
4. 构建命令留空，输出目录为根目录
5. 部署完成后，在项目 Settings → Environment variables 里添加 `BACKEND_URL`（见第二节）
6. 保存后重新部署一次使环境变量生效

### 方式 2：Wrangler 命令行

```bash
# 安装 wrangler
npm install -g wrangler
wrangler login

# 在本目录下部署
cd cloudflare-pages
wrangler pages deploy . --project-name=vidora

# 设置后端地址（secret 方式，更安全）
wrangler pages secret put BACKEND_URL --project-name=vidora
# 提示时粘贴你的后端 https 地址
```

## 四、验证是否成功

1. 打开 Pages 分配给你的域名，如 `https://vidora.pages.dev`
2. 浏览器访问 `https://你的域名/api/health`
   - 返回 `{"ok":true,...}` 表示 API 转发正常
   - 返回 "后端未配置" 表示没填 BACKEND_URL
   - 返回 "连接后端失败" 表示后端没启动或地址不对
3. 在页面里选平台、填房间号解析，能出结果即全链路打通

## 五、常见问题

- **解析一直失败**：先看 `/api/health` 是否正常；正常则说明转发没问题，是后端解析本身失败（房间未开播/接口变更）。
- **播放转圈**：Pages Function 对长连接流支持有限，若在线播放不稳定，请点结果里的"下载.m3u8用本地播放器打开"，用 PotPlayer/VLC 播放。
- **CORS 报错**：代理函数已统一加 `Access-Control-Allow-Origin: *`，正常不会出现。
- **为什么不全用 JS 重写解析**：直播平台的签名算法依赖 Python 加密库和 Node 执行环境，Workers 运行时无法兼容，强行重写成本极高且极不稳定，故采用"前端上云、后端保留"的混合架构。

---

## 六、安全提醒

Pages Function 的 `/api/stream` 会被用来转发任意 URL，理论上可作为开放代理。个人使用无妨，但若公开分享域名，建议：
- 在 `functions/api/[[path]].js` 里给 target 加域名白名单；
- 或开启 Cloudflare 的访问控制（Access）限制访问来源。
